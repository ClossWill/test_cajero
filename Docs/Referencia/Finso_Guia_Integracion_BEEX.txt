Nota de Ingeniería:  Diego, para el desarrollo del "Agente ATM" local en C# .NET, se analiza a continuación la
factura proforma original de Hongzhou Technology HK Ltd. No existe un "SDK único de la máquina" porque un
cajero industrial es un ecosistema híbrido compuesto por 23 partidas de hardware de distintas marcas integradas
en un gabinete de acero. A continuación se define la naturaleza de cada componente y cómo se integra en el flujo
lógico de software.
1. Componentes Core que Requieren Programación Directa (Librerías / Protocolos)
Estos componentes representan el núcleo transaccional del Agente ATM. Requieren mapeo de bytes, inyección de
archivos fuente o consumo de SDKs provistos en las carpetas de integración:
Part. Componente / Modelo Especificación de Hardware Dictamen Técnico para Desarrollo (Diego)
5 Cash recycler with shutter
GRG 9250N
Recicladora de 4 casetes de
aceptación (2,850 notas c/u) +
Shutter.
Inyección directa de código fuente: No busques
una DLL cerrada. Utiliza el archivo abierto 
CRM9250N.cs  incluido en la carpeta de GRG.
Arrástralo a la solución .NET; este contiene los
métodos y envoltorios nativos de comunicación
con la recicladora.
7 Coin dispenser
MK4 * 2 PCS
Dispensador doble de
monedas. Capacidad
multimoneda. 3 monedas/seg.
Programación por protocolo serial: Se maneja
mediante la norma técnica estándar de la industria
ccTalk. Utiliza una librería genérica ccTalk de
código abierto en C# e implementa los bytes de
comandos específicos detallados en las tablas de
Excel de la carpeta de integración.
8 Passport scanner
MEPR500+
Sensor CMOS 3.1 MP, 400
DPI. Lectura RFID e Infrarrojo
(ICAO 9303).
Consumo de SDK Propietario: Este periférico
cuenta con su propio SDK de procesamiento
OCR. Debes invocar sus funciones en segundo
plano desde el Agente para recibir el string con los
datos validados del usuario (Nombre, ID,
Nacionalidad) para el motor de KYC.
9 Receipt Printer
KP-80A
Impresora térmica de 80mm
con autocortador. Velocidad
250mm/s.
Comandos Estándar: Conectada vía USB/Serial.
No requiere SDK complejo; se programa mediante
comandos genéricos de impresión industrial ESC/
POS estándar para dar formato y emitir el ticket de
confirmación al usuario.

2. Sensores, Seguridad y Periféricos con Comunicación Automatizada
Componentes integrados que reportan eventos de estado de forma reactiva o que operan de manera autónoma sin
necesidad de lógica transaccional compleja por parte del backend:
Part. Componente / Modelo Especificación de Hardware Dictamen Técnico para Desarrollo (Diego)
16 Multifunctional serial control
module
ALB02
Módulo de control serial.
Concentrador de sensores
internos.
Escucha Serial Reactiva: Esta placa concentra
el switch de intrusión (apertura de puertas),
sensor de vibración (anti-vandalismo) y
proximidad. Envía cadenas de bytes automáticas
a través de puerto COM. El Agente solo debe
escuchar este puerto y detonar alertas al
Middleware en AWS si el estado cambia.
10 QR code scanner
XZG004
Escáner 1D/2D, CMOS
1280x800 píxeles.
Cero Programación (Plug & Play): Configurado
de fábrica bajo el modo emulación de teclado
(HID-KBW). Al pasar el código QR de la aplicación
móvil frente al cristal, el dispositivo "teclea" la
cadena alfanumérica directamente en el foco de la
pantalla de la interfaz de usuario.
11 Camera+NVR for face & cash
acceptor
Hikvision Ecosistema
NVR DS-7604NI-Q1 +
Cámaras pin-hole IP840 +
Disco Duro 1TB.
Ecosistema Autónomo Cerrado: Es un circuito
de seguridad independiente que graba de forma
automatizada en el disco local de 1TB. No
requiere que el Agente gestione el
almacenamiento. Únicamente si requieres
visualización en vivo dentro de la app, se
consumirá el API de red local de Hikvision.
12 Camera (face recognition)
GDZS-DC004-MG3021
Cámara USB nativa. Píxeles:
Luz visible 300W / Infrarrojo
200W.
Dispositivo de Video Estándar: Es detectada
nativamente por el Kernel de Windows 11 IoT
como una cámara web genérica USB. Se integra
de manera directa utilizando librerías estándar de
captura multimedia de .NET o wrappers de
OpenCV.
